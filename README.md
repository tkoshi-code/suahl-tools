# スアール営業支援アプリ

スアールのクイズイベントで使用する進行・ルール表示PWAです。Flip 7、カスタムスロットミリオネア、文字あてWordle、出張営業チームクイズ、コーナー説明、告知スライド、休憩表示、Spotifyイントロクイズなどをまとめています。

## 公開サイト（現行）

https://tkoshi-code.github.io/suahl-tools/

`master` ブランチへpushすると、GitHub Actionsが自動的にビルドしてGitHub Pagesへ公開します。

## 主な画面と機能

- ホーム: イベント情報とクイズコーナーの選択
- Flip 7: クイズ正解者がカードを引くゲーム
- カスタムスロットミリオネア: 最大4チームで、10問の正解数に応じてスピンし、カードでスロットを強化する対戦ゲーム
- 文字あてWordle: クイズに正解したチームが、相手チームの秘密の5文字を予想する2〜3チーム戦
- ボードラッシュ: チーム名を設定できるデュース対応得点表とルール説明ページ
- 出張営業チームクイズ: 5名×5チームの3ラウンド戦、回答席・ジャンル・タイマー付き会場表示、個人決勝2連単予想、任意の追加枠を含む5○3×
- Spotifyイントロクイズ: QM操作画面と会場表示
- 告知・休憩表示: 会場スクリーン向け表示

## 文字あてWordle

2〜3チームで遊びます。各チームは、同じ文字を2回使わない秘密の5文字を設定します。別チーム同士で同じ秘密ワードを設定しても構いません。クイズに正解したチームを選び、続いて攻撃する相手チームを選ぶと、その相手の秘密ワードを1回予想できます。

- 赤: 文字と場所の両方が一致
- 黄: その文字は使われているが場所が違う
- 灰: その文字は使われていない

濁音・半濁音・小さい文字・長音は別の1文字として扱います。全角・半角は入力時に統一します。秘密ワード内では同じ文字を使えませんが、予想する言葉では同じ文字を使えます。重複文字の判定は、秘密ワードに存在する数を超えた分を灰色にします。秘密ワードを当てられたチームは撃破となり、最後まで秘密ワードが残ったチームが勝利です。

チーム別の表示板には予想履歴と色判定が残ります。直前の予想は取り消しでき、進行状態は `piyopiyo_wordle_v1` へ自動保存されます。JSONバックアップと復元にも対応します。バックアップには秘密ワードが含まれるため、共有前に内容を確認してください。

操作用画面の「会場表示を開く」から、投影専用ウインドウを起動できます。チーム名と秘密ワードの登録、攻撃先選択、予想入力は操作用画面だけで行います。会場表示用の同期データには未正解の秘密ワードを含めず、ゲーム開始前は「準備中」だけを表示します。撃破されたチームの答えは公開し、最後に残った勝者の答えは操作用画面で「答えを公開」を押すまで非公開のままです。

操作用・会場表示用の両画面にある各チームの「全履歴」から、過去の予想を件数に応じて複数列へ自動整列し、スクロールなしの一画面で確認できます。「未使用の五十音」では、そのチームへの予想にまだ登場していない清音・濁音・半濁音・小書き文字・長音を表示します。どちらの表示も開閉操作をもう一方の画面へ同期します。シンキングタイマーは30秒を初期値とし、操作用画面のスタートボタンを押してから減少します。一時停止・再開・30秒へのリセットができ、0秒になっても自動でゲームを進めません。

## ボードラッシュ

2チームの名前と先取ポイントNを設定できる得点表です。問題進行と5秒カウントはQMが別途行い、画面では両チームの得点と勝利条件を大きく表示します。得点は各チームの±1ボタンで記録し、直前の操作を取り消せます。

設定したNpt以上かつ2pt差で勝利となり、1pt差の間はデュース表示を続けます。勝利条件を満たすと優勝表示を出します。チーム名と勝利条件は得点を残したまま変更できます。

「ルール説明」ページには、早押し、押された箇所までの再読、5秒ボード回答、一斉オープン、正解者数による得点、デュース、読み切り無効を順番に表示します。得点表は `piyopiyo_board_rush_v1` へ自動保存され、JSONバックアップと復元に対応します。

## カスタムスロットミリオネア

2〜4チーム、勝利VP（50 / 75 / 100 / 200 / 300のプリセット、または10〜9999VPのカスタム入力）、カード検討時間（60 / 90 / 120秒）、出題内容3リール、共有山札のカード別枚数（各0〜99枚）を設定します。リール設定とカード枚数は保存・JSONバックアップの対象です。

出題内容スロットは左から「出題形式」「難易度」「ジャンル」の3リールです。各リールの見出しと候補を1行ずつ自由に登録できるため、「イントロ」「画像問題」などイベントに合わせた条件へ変更できます。各ラウンドの10問開始前に抽選し、決まった3項目は10問が終わるまで操作画面へ表示されます。旧保存データの標準3項目も、内容を保ったままこの順へ並べ替えます。

1. ゲーム開始時に全チームが1回ずつスピンする
2. 初回スピン直後からチーム数+1組の3枚カードセットを公開し、VPが低いチームから1セットずつ選ぶ
3. 相談時間の目安を見ながら各チームが獲得カードを使用し、準備ができたら出題内容スロットへ進む。タイマーが0秒になってもカード操作は継続できる
4. 出題内容スロットを回し、出題形式・難易度・ジャンルなどを決めてから10問を開始する
5. 1ラウンド10問のクイズを行い、正解のたびにチームのクレジットコインを1枚増やす。スルー時は没収ポットへコインを1枚入れてスルー数を可視化する
6. 10問終了後、各チームがクレジット数と同じ回数をまとめてスピンする。スピン開始時にコインを1枚消費する
7. 全チームのスピン後は再びカードセット選択と育成を行い、次の出題内容スロットへ進む

初期数字山札は1×4枚、2×4枚、3×3枚、7×1枚です。共有のナンバーカードは標準設定で「1/2」「3（+1VP）」「3（+2VP）」「7」が各8枚です。1/2は判定ラインごとに1または2として扱い、ボーナス付き3は揃わなくても盤面に出た枚数分のVPを得ます。

カードは自分のスロットを育てるものだけです。標準設定の強化カードはリムーブ7枚、ダブルリムーブ2枚、ワンツービート、ラッキーナンバー、ビッグナンバー、スモールナンバー各3枚です。リムーブは数字山札から1枚、ダブルリムーブは最大2枚を除外します。山札はどちらも最低10枚です。各カードの枚数はゲーム開始前に変更でき、ルール画面にも現在の構成を表示します。ワンツービートは1・2・1/2が3枚出るごとに、現在レベルと同じVPを加算します。リスクリターンは使用しません。倍率カードは横×1、縦×1・×2、斜め×1・×2を任意の対応ラインへ置きます。妨害・チャレンジカードも使用しません。

カード名は大きく表示し、PCではカードへマウスを重ねるか手札カードへキーボードフォーカスを移すと効果説明を前面表示します。タッチ端末では説明をカード内へ常時表示します。画面上部には各チームのクレジット数とコイン、スルーで没収されたコインをまとめて表示します。盤面上の実線が現在の有効ラインです。無効ラインは盤面上へ重ねず、横・縦・斜めのライン一覧でOFF表示します。各チームの数字山札は「現在の数字セット」として、カード種類ごとのチップ・枚数・合計枚数を表示します。PCのスピン中は画面の高さへ自動で収め、アクティブチームを中央の「リール」と「ライン倍率」の左右2列へ配置します。成立ラインは `HIT 数字×倍率＝獲得VP` と強調し、全チームの小型リールは左右へ最大2チームずつ配置します。「いまやること」と進行情報は横並びに圧縮し、3列は時間差で停止して結果を確認してから次へ進みます。狭い画面では1列表示と通常スクロールへ自動で切り替わります。

カードドラフトは専用の比較画面として表示します。PCでは最大5組のSET A〜Eを横一列に並べ、各セットの3枚を同じ位置で比較できます。ドラフト順にはチーム名と現在VPを表示します。「現在のスロット」にカーソルを重ねるかタップすると、選択中チームの3×3リール、有効ラインと倍率、数字セット、強化バッジをカードへ重なるプレビューで確認できます。狭い画面ではカードセットを2列または1列へ自動で切り替え、プレビューは縦配置になります。

進行バーまたは優勝画面の「📈 得点推移」ボタンから、開始時・初回スピン終了時・各ラウンド終了時のチーム別累積VPを折れ線グラフで確認できます。チームのスピン処理順は横軸へ分けず、同じラウンドの全チームを同じ横位置でまとめて更新します。履歴が増えても開始から最新までをグラフ横幅100%へ均等に表示し、横軸ラベルは重なりを防ぐため自動で間引きます。旧保存データのスピン単位履歴も、各ラウンドの最後の得点へ自動的にまとめます。履歴はゲーム状態とJSONバックアップへ保存されます。

出題内容スロットと対戦スロットの待機中・結果確認中は、画面ボタンのほかEnterキーまたはSpaceキーで「回す」「10問開始」「次のスピンへ／次のチームへ」を進められます。Enter／Spaceを送るUSB・Bluetoothボタン、ゲームパッドのAボタンにも対応します。外部コントローラーからブラウザへ連携する場合は、ページ上で `window.dispatchEvent(new Event('custom-slot-spin'))` を実行すると現在必要な操作を呼び出せます。

ワンツービート、ラッキーナンバー、ビッグナンバー、スモールナンバーは、効果内容と累積レベルを色分けバッジで表示します。3（+1VP）は水色、3（+2VP）は紫色のリールセルとVPラベルで強調し、ライン成立のオレンジ色とは区別します。

ラッキーナンバー、ビッグナンバー、スモールナンバーが得点を改善する場合は、リールを元の数字で停止した後、対象マスを専用色・専用SEで発光させ、対象リールだけを縦へ滑らせて変更後の数字で停止します。結果確認中も対象マスへ「変化前→変化後」を残すため、どの強化が作用したか追跡できます。

画面上部からBGMとSEを個別にON/OFFでき、それぞれ0〜300%で音量調整できます。100%が従来音量で、会場設備に合わせて最大3倍まで増幅できます。設定値はゲーム状態と一緒に保存・復元され、新しいゲームへも引き継がれます。BGMは新しいゲームを120 BPMで開始し、ラウンドごとに5 BPM、先頭チームが目標VPの80%へ到達するとさらに10 BPM上がり、最大165 BPMまで数秒かけて滑らかに変化します。現在BPMはBGMボタンに表示します。BGM、回転開始・回転中・各列停止・はずれ・当たりのSEはブラウザ内で生成するため、外部音源への通信や音源ファイルは不要で、オフラインでも再生できます。ブラウザの自動再生制限により、BGMは利用者がBGMボタンを押した後に開始します。

7が有効ラインに揃った場合は通常の当たり音へ上昇フレーズ・低音・きらめき音を重ねたジャックポットSEを再生します。規定VP到達後に勝者が確定すると、再生中のBGMを停止して約2秒の優勝ファンファーレを1回再生します。これらはSEのON/OFFと音量設定に従います。

勝利判定は全チームのラウンド内スピンが終わった時点で行います。複数チームが目標VPへ到達した場合はVPが最も高いチームを勝者とします。

ゲーム状態は `piyopiyo_custom_slot_v1` として自動保存されます。進行ログ欄からJSONバックアップと復元ができます。

## 出張営業チームクイズ

ホームの「出張営業チームクイズ」から、5チーム・各5名を登録して進行します。

1. 1st Round: 各チーム2名が同時参加し、正解者は勝ち抜けて次のメンバーへ自動交代。5名を固定順で並べ、回答席・勝ち抜け・待機を色とマークで表示。初期配点は完走順に5 / 4 / 3 / 2 / 1pt
2. 2nd Round: 5ジャンル。ジャンルごとに問題数と各チームの代表2名を設定し、初期配点は正解1問につき1pt
3. 3rd Round: 設定時間いっぱいのノンジャンル。初期配点は正解1問につき1pt
4. 3ラウンド合計で優勝チームを決定し、個人決勝の進出者一覧と1着・2着を順番通りに当てる2連単予想ルールを表示
5. 優勝チーム5名に、必要なら他チームから1名だけ追加して5○3×の個人決勝

準備画面で5ジャンルの名称・問題数、1stの順位別配点、2nd・3rdの正解1問あたり配点を編集できます。配点変更後は、保存済みの順位・正解数から総得点を自動再計算します。

2nd Roundの代表者プルダウンは、選択済みの名前を明るい文字と緑枠で強調します。候補リストも白背景・濃い文字で表示します。

2連単予想は説明表示のみで、予想内容の入力・集計は行いません。1着と2着の2名を着順通りに予想します。追加参戦は任意で、「追加参戦なし」または優勝チーム以外の20名から1名を選べます。

出張営業の運営画面と会場表示は、参加者名・状態・配点・操作ラベルを大きめに表示し、スマートフォン操作と会場スクリーンの両方で読みやすい文字サイズにしています。

同点時はサドンデスの正解を3rd Roundへ加点して決着させます。会場表示は既存の外部得点表ではなく、このイベント専用の内製画面です。別ウインドウで起動し、1stの5名全員の回答席・勝ち抜け・待機、2ndの現在ジャンル・問題番号・代表2名、3rdの残り時間、ラウンド別得点・総合順位を自動更新します。

準備画面の「会場表示リンク」からURLのコピーまたは画面起動ができます。URLは `?view=sales-score` で開き、`#` 以降の `t1`〜`t5` にチーム名、`p1_1`〜`p5_5` に25名の名前、`g1`〜`g5` と `q1`〜`q5` にジャンル名・問題数、`r1`〜`r3` に配点を出力します。URLフラグメントを使うため、名前はGitHub Pagesへのリクエストに含まれません。URLを別端末で開いた場合も名前とイベント設定は引き継がれますが、進行と得点のライブ同期は同じブラウザ内の別ウインドウに限られます。

進行状態は `piyopiyo_sales_event_v1` として自動保存され、画面下部からJSONバックアップ・復元・全初期化ができます。

## スマートフォンへの導入

公開サイトをSafariまたはChromeで開き、ブラウザメニューから「ホーム画面に追加」または「アプリをインストール」を選びます。一度オンラインで読み込むと、Service Workerのキャッシュからオフライン起動できます。

## データ保存とバックアップ

入力・ゲームデータはブラウザのlocalStorageだけに保存し、自動送信しません。文字あてWordle、ボードラッシュ、カスタムスロット、出張営業チームクイズ、Spotifyイントロクイズは、それぞれの画面からJSONを出力・復元できます。ブラウザのサイトデータを削除する前に必要なJSONを保存してください。

詳細は [PRIVACY.md](PRIVACY.md) を参照してください。

## ローカル起動

`npm run build` 済みであれば、プロジェクト直下の `index.html` をブラウザで直接開けます。ファイルとして開いた場合は、ESモジュールを使わない `dist/index.html` へ自動で切り替わります。`dist` がない場合は白画面にせず、ビルド手順と配布版を開くボタンを表示します。

開発中は次のローカルサーバー方式を使用します。

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

ブラウザで `http://127.0.0.1:5173/` を開きます。

## ビルド確認

```sh
npm run build
```

ビルドではブラウザのローカルファイル制限を受けないクラシックスクリプト形式を `dist` へ生成します。ビルド後、必要に応じて `npm run preview` でService Workerを含む本番相当表示を確認します。

## Spotifyイントロクイズ

トップ画面下部の「ツール」からQM操作画面を開きます。

- Spotifyの曲共有URLと、会場に表示する答えを登録
- サビ開始位置の登録有無にかかわらず、通常出題は必ず曲の先頭から開始し、3～30秒の指定時間で自動停止
- 回答者の誤答などで手動停止した後は、停止位置と残り時間からワンタップで再開
- 曲ごとにサビ開始位置を秒数で登録し、「答え表示＋サビ再生」を押したときだけ、サビ位置への移動完了後に答え表示とサビ再生
- 未出題曲からランダムに次の曲を選択
- QM画面とは別の会場表示ウインドウへ、カウントダウン、答え、ジャケット画像を送信
- 登録曲をJSONでバックアップ・復元

Spotifyプレーヤーには曲名が表示されるため、QM操作画面は会場のスクリーンには映さず、「会場表示を開く」で開いたウインドウを使用してください。ブラウザの自動再生制限により音が出ない場合は、Spotifyプレーヤー内の再生ボタンを一度押します。

登録曲、再生時間、曲ごとのサビ開始位置、取得済みジャケット画像URLは `piyopiyo_spotify_intro_v1` としてブラウザのlocalStorageに保存されます。Spotifyのアカウント情報やOAuthトークンは保存しません。再生時にはSpotifyの公式埋め込みプレーヤーへ通信し、曲をセットしたときは公式oEmbed APIからジャケット画像URLを取得します。画像を取得できない場合も、再生と答え表示は利用できます。

店舗イベントでの利用に必要な楽曲の権利とSpotifyの利用条件は、運営側で事前に確認してください。

### 初級スターターJSON

[public/data/spotify-intro-starter.json](public/data/spotify-intro-starter.json)を、答えやすいイントロ曲の共有カタログとして管理します。QM画面の「JSONから追加」を押すと、新しく追加された曲だけが端末へ追加されます。登録済みの曲や利用者が編集した答えは削除・上書きしません。

各曲にはSpotify URLのほか、`title`、`artist`、`difficulty`、`category`、`decade`、`recommendedSeconds`、`note`を持たせています。利用者が曲を編集すると任意の `chorusSeconds`、曲をセットして画像取得に成功すると `artworkUrl` も保存されます。今後は同じ形式で曲を追加し、`catalogVersion`を更新します。
